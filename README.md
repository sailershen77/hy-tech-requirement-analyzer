# HY Tech Requirement Analyzer

> 从 `.docx` 项目需求书中提取**技术需求**，输出结构化 Markdown；若文档含**评分表**，同步输出技术评分表部分。

适用于软件/IT 项目需求书、采购需求书、招标文件、技术规格书等——凡含"技术需求/技术要求/技术参数"章节或评分标准的 docx 均可分析。

## 功能特性

- **docx 解析**：自动提取段落（含标题层级）与表格，保留文档原始顺序，输出结构化 JSON 供分析
- **技术需求提取**：按章节标题定位技术需求区域，通过约束词（必须/应/宜/可）与量化指标（≤/≥/TPS/秒/GB）识别需求语句
- **7 类分类体系**：架构 / 功能 / 性能 / 安全 / 接口集成 / 运维部署 / 其他，按内容自动归类
- **约束程度判定**：必须 / 建议 / 可选，按约束词自动判定
- **评分表识别**：通过表头特征（评分项/分值/评分标准）区分评分表与技术参数表，商务报价表不输出
- **忠实原文**：技术需求与评分表内容忠实于原文，不增删、不润色、不虚构；无评分表时如实说明

## 目录结构

```
hy-tech-requirement-analyzer/
├── SKILL.md                        # Skill 主指令 — 7 步分析工作流
├── references/
│   └── extraction_guide.md         # 技术需求识别规则 + 评分表识别特征 + Markdown 输出规范
└── scripts/
    └── extract_docx.py             # docx → 结构化 JSON（段落 + 标题层级 + 表格）
```

## 依赖

提取脚本依赖 `python-docx`：

```bash
pip install python-docx
# 国内镜像加速
pip install python-docx -i https://pypi.tuna.tsinghua.edu.cn/simple
```

## 使用方式

### 在 WorkBuddy 中使用

安装本 Skill 后，直接在对话中触发：

```
分析这份需求书的技术需求    +  提供 docx 文件
提取技术需求               +  提供 docx 文件
技术需求分析
```

### 独立运行提取脚本

```bash
python scripts/extract_docx.py input.docx --output extracted.json
```

输出 JSON 结构：

```json
[
  {"kind": "paragraph", "text": "...", "style": "Heading 1", "heading_level": 1, "idx": 0},
  {"kind": "table", "rows": [["...", ...], ...], "idx": 5}
]
```

## 工作流（7 步）

1. **确认输入并提取 docx** — 运行 `extract_docx.py` 转为结构化 JSON
2. **加载提取指南** — 读取 `references/extraction_guide.md`
3. **定位技术需求章节** — 按标题模式定位，无明确标题则全文降级扫描
4. **提取并分类** — 按约束词/量化指标识别需求，归入 7 类分类体系
5. **识别评分表** — 按表头特征判断，记录完整行列数据
6. **生成 Markdown** — 技术需求表格 + 技术评分表
7. **保存并展示** — 输出 Markdown 文件

## 输出示例

```markdown
# XX市智慧政务平台建设项目需求书 - 技术需求分析

> 文档信息：XX-2026-001 | 分析日期：2026-08-19

## 一、技术需求

### 1. 系统架构类

| 序号 | 技术需求 | 分类 | 约束程度 | 备注 |
|:---:|:---|:---:|:---:|:---|
| 1 | 系统应采用B/S架构，基于微服务框架开发，支持容器化部署 | 架构 | 必须 | 2.1节 |

### 2. 性能需求类

| 序号 | 技术需求 | 分类 | 约束程度 | 备注 |
|:---:|:---|:---:|:---:|:---|
| 5 | 系统首页平均响应时间应不超过3秒；核心业务接口吞吐量应不低于500 TPS | 性能 | 必须 | 2.3.1节 |

## 二、技术评分表

> 评标采用综合评分法，总分100分，其中技术部分65分，商务部分35分。

| 序号 | 评分项 | 分值 | 评分标准 |
|:---:|:---|:---:|:---|
| 1 | 技术方案 | 20 | 方案完整、合理、可行，满足需求书要求得20分 |
```

## 关键原则

1. **忠实原文**：不增删、不润色、不虚构
2. **技术需求优先**：商务、资格、评标办法说明不进入技术需求清单
3. **量化优先**：完整保留量化数值（如"不超过3秒"不可省略）
4. **无表不虚构**：未发现评分表必须如实说明，不得编造评分标准
5. **Markdown 输出**：最终交付物是 Markdown 文档
